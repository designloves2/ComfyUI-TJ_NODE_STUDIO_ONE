## B. Browser code to port
1. **Translation: no line-by-line flood** — `web/shared/bilingual.js` `translateText`: the one-line-at-a-time fallback runs only when the text has at most `MAX_LINES_ONE_BY_ONE = 12` lines; a longer text throws `Translate failed: <reason>.` right after the two whole-text attempts.
2. **LLM settings save only the changed keys** — `web/shared/llm_panel.js` `mountLLMSettingsSection`: the panel's `llm` object is a Proxy that records the assigned keys (`dirty`); `saveLLM()` saves only those. Before, it saved the whole copy taken when the panel was built and put old values over what another node / page / tab had saved (a model or backend changed meanwhile). Apply the same idea wherever the web LLM settings panel saves.
3. **No hidden OpenRouter model in the UI** — `llm_panel.js` `box._fill`: an empty model is no longer auto-set to gemini (or the first model); the list gets a first option `— choose a model —` (value `""`). Same in the Translation LLM panel (`shared/translation_settings.js`, H3 `ui_app_settings_minimax.js` `translationTab`: `["", ...ms]`). Remove any gemini auto-pick in the web code.
4. **Image nodes, Prompt Refine result** — `llm_panel.js` `_showRefineResult(refined, protect, withKo)` replaces `_showRefineCompare` and `_diffOriginal` (both deleted: no word comparison, no red highlight). Window "🔧 Prompt Refine result": left textarea `English (you can edit it before applying)`, right read-only textarea `한국어 (번역)` with the veil `⏳ 번역중 (한국어로)…` while `translateText(refined, "ko", translateLlm(), { protect })` runs; buttons `Re:Refine`, `Apply`, `Close`. It resolves `{ action, text, ko }`; `ko` is the translated text, or `""` when the English was edited after the translation. `runRefine({ getText, onApply, setBusy, protect, withKo })` calls `onApply(text, ko)`; `setResult(text, ko)` writes both slots (`fieldSetBoth(o, k, text, ko)`) and only runs the background `fieldFill` when `ko` is empty and Korean is on.
5. **Image -> Prompt Write works from the image alone** — `llm_panel.js` `doWrite`: the text already in the Prompt Edit box is sent only when the checkbox is ticked (`existingText = useExistingChk.checked ? existingTA.value.trim() : ""`). Checkbox under the Write button, `writeCol` = Write button + label `llm_chk_use_existing` (ko `기존 글 반영 (칸의 글을 이미지와 합침)`, en `Use the existing text (merge the box with the image)`, keys in `shared/i18n.js`), default off, remembered as `write_use_existing` in the shared LLM settings.
6. **"한글 번역 사용" per node** — new `web/shared/ko_setting.js` (`getUseKo(node)`, `setUseKo(node, on)` → `localStorage["tj_use_ko_<node>"]` = "1" | "0", default on, event `tj-use-ko`; `nodeKeyOf(el)` = `el.closest("[data-tj-node]").dataset.tjNode`; `useKoFor(el)`; `useKoCheckbox(node, theme)`). Each node's root element gets `data-tj-node="<key>"` (krea2, qwen21, qwen2511, anima, klein, moss, sdxl, zimage, minimax_h3, ltx25). Checkbox `한글 번역 사용` at the top of the node's Translation settings. **Off = no AUTOMATIC translation only**: no translation before Generate (`ensureEnglishPrompts` / `bilingual_image.js` `ensure()` / LTX guard are skipped), no background Korean fill after Write / Refine (`fillKoLater`, `setResult`), the Refine result's Korean side waits for its `EN → KO` button. The EN / 한 button and `↻` stay and translate once each time they are pressed.
7. **Settings tabs and the Translation setting in every node** — the image nodes' Settings were one long scroll; now `Model / LLM / Translation` tabs (`web/shared/settings_tabs.js` `tabSettings(ov, llmPanel, { brand, bg, border, nodeKey })`), the Prompt Edit popup's `설정` button opens the LLM tab (`showTab("LLM")`). `web/shared/translation_settings.js` `translationSettingsPanel(theme, nodeKey)` is the same Korean <-> English backend / model choice as the H3 tab (one server-side setting, re-drawn on the `tj_translate_config` push). LTX 2.5 Settings got a `Translation LLM` tab. Mirror it where the web node settings are a single list.
8. **Qwen Image 2.1: Settings behind the Prompt Edit popup** — the settings overlay had `zIndex` 9996 under the popup's 9997; it is 9998 now (every other image node already had 9998). Check the web twin for the same.

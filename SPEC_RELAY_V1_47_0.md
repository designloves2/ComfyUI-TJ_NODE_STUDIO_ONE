## 1. 7+1 Upscaler switch (Turbo -> 7+1, Turbo LoRA or None)

State: `hiresUpscaler` "h3" | "kimchy" (default "h3"; anything else = "h3"). Presets (`RECIPE_KEYS`): add `hiresUpscaler`, `hiresKimStartMp`, `hiresKimFinalMp`. Clip meta: save `hiresUpscaler`, `hiresKimStartMp`, `hiresKimFinalMp`; Reuse restores them (`hiresUpscaler` falls back to "h3").
Start / Final MP are kept per upscaler: A uses `hiresStartMp` / `hiresFinalMp` (defaults 0.7 / 1.6), Kimchy uses `hiresKimStartMp` / `hiresKimFinalMp` (defaults 0.5 / 2.0). Helper `hiresMp(state)` returns the pair of the selected upscaler; the size line, the graph and the fields all use it; typing in a field writes the selected upscaler's key.
Why 1.6 vs 2.0: the H3 Latent Upscaler runs the last step on the whole picture (16 GB VRAM: above 1.6 MP it spills to the CPU, an hour or more); Kimchy samples in tiles, 2.0 MP is fine.

Graph (`buildHiresStage` in `web/minimax/graph_builder_minimax.js`):
- A: unchanged (LTXVSeparateAVLatent -> MinimaxH3LatentUpscaler3D -> LTXVConcatAVLatent -> [TJ_H3_AudioLock] -> model chain -> BasicGuider -> SamplerCustomAdvanced).
- Kimchy: no Separate / Upscale / Concat / AudioLock and no BlockSparseAttention. One node `KimchyH3ZeroSplitMP` with inputs: `model` = the stage model after H3MemoryOptimization (after the sigma shift when "Bypass H3 Memory Optimization" is on), `conditioning` = stage-2 conditioning, `latent` = the stage-1 sampler's `denoised_output` (output index 1, the whole AV latent), `noise`, `sampler`, `sigmas` = low_sigmas of the SplitSigmas, `negative` = ConditioningZeroOut(conditioning), `model_name` "minimax_h3_latent_upscaler_3d_bf16.safetensors", `upscale_by` "megapixels", `target_megapixels` = Final MP, `scale` 2, `align` 32, `precision` "fp16", `cfg` 1, `color_match` true. Its output latent goes to the same decodes. Final MP outside 1.0-8.5 throws "H3 Kimchy Up Scaler supports Final MP 1.0 – 8.5.".
- First/Last clips with Kimchy: stage-2 conditioning is built WITHOUT first/last frames and without library assets (Kimchy samples in tiles; a keyframe block cannot be cut into tiles - without this the run fails with "shape mismatch [3894, 96] ... [1232, 96]"). Reference clips keep their references.
- Missing pack: throw "7+1 H3 Kimchy Up Scaler needs the ComfyUI-Kimchy-Minimax-H3-Suite pack — install it (github.com/AI-KIMCHY/ComfyUI-Kimchy-Minimax-H3-Suite), or pick H3 Latent Upscaler." Availability: add `KimchyH3ZeroSplitMP` next to `MinimaxH3LatentUpscaler3D` in BOTH availability lists (`web/minimax/api_minimax.js` and `nodes.py`), else the UI says "not installed".
- Panel texts: when Kimchy is selected show the "not installed" warning for `KimchyH3ZeroSplitMP` and the hint "Kimchy runs the upscale and the last step in one node (Sol-Attn is not used). Final MP must be 1.0 – 8.5."
- Installer: `install_requirements.bat` REPOS[29] and `install_requirements.sh` get https://github.com/AI-KIMCHY/ComfyUI-Kimchy-Minimax-H3-Suite. README: external project, Apache-2.0, link to its LICENSE, we only call its node; nothing is copied.

## 2. Postprocess -> C. Upscale

### 2a. "LTX 2.5 Upscale" (value `ltx`)
Panel: label "UPSCALE SETTING" with Steps / Denoise / Sampler / Scheduler (same fields and defaults as the old LTX Upscale mode: 4 / 0.15 / euler_ancestral / simple), then the **Split mode** control (only for this method), then label "LTX LoRA" with the LTX LoRA list. "Post finish" = the existing "2-pass: run RTX VSR (TJ) on the result" checkbox, nothing else. Hint: "The prompt comes from the clip's own ONE STUDIO meta, otherwise it is written from sampled frames. Split mode cuts a long clip into pieces (each continues from the last frame of the one before) and joins them; Preview always runs the range in one pass."
Graph: `buildLtxUpscaleGraph(state, avail, { into: { g, images, audio }, fps, anchorImage })` adds the LTX refine to the Postprocess graph (VAEEncode -> LTXVLatentUpsampler -> first-frame anchor -> concat with the encoded audio -> sampler -> decode); the audio of the result is the LTX-decoded audio. LTX models come from Settings -> LTX 2.5 Upscale; missing ones throw "Set the LTX 2.5 models in ⚙ Settings first — missing: ...".
Prompt: ONE STUDIO meta prompt first (an H3 brief - detected by `[Shot`, `<Picture`, `subject_definitions`, `technical_settings` or `integrated_multimodal_description` - is rewritten as an LTX prompt by the LTX LLM; an LTX prompt is used as is); no meta -> frames -> vision -> LTX prompt. Failure stops the run with an error, never an empty prompt.
Split mode (`ltxSegmentPasses`, `ppRunSegments`): By seconds / By count as in the old mode; pieces are 8n+1 frames; only Generate splits (Preview does not). Each piece is its own Postprocess graph (same chain), `skipFirstFrames`/`frameLoadCap` = the piece window, suffix `_segNN`, and the piece's LTX anchor = the previous piece's last frame (`getClipLastFrame`); pieces are joined with the stitch route under the normal Postprocess name and the piece files are deleted.

### 2b. "Latent Upscale (Use H3)" (value `h3lat`)
Re-runs only the last step of a finished 8-step H3 clip. Panel (own state `pp*`, independent of the main H3 modes), in this order: Turbo select ("Turbo LoRA (Basic)" `pdd` | "None (8-step checkpoint)" `none`); if pdd: "Turbo LoRA (Basic)" slot and "Turbo LoRA (Reference)" slot (a ● marks the one the clip uses) and "lora strength"; "Model" slot switch "Same as generation" | "Fixed model" with the resolved file name under it (Same = Settings' First/Last UNET for FL2VA clips, Reference UNET for Reference clips; Fixed = Settings' "UNET - 7+1 last step"); "Upscaler" switch (section 0); for Kimchy the select "Latent upscale": "Neural (Kimchy's trained upscaler)" | "Bicubic (plain interpolation)" | "Trilinear (plain interpolation)" (`neural`/`bicubic`/`trilinear`; Kimchy `model_name` "None (Bicubic)" / "None (Trilinear)" for the last two); checkbox "Bypass H3 Memory Optimization"; "Final MP"; "Activation chunk rows"; then the hint text of `one_node_minimax_h3.js`.
State keys: `ppH3TurboMode`, `ppH3PddFile`, `ppH3PddFileReference`, `ppH3PddStrength`, `ppH3LastFixed`, `ppH3Upscaler`, `ppH3UpModel`, `ppH3FinalMp` (1.6), `ppH3KimFinalMp` (2.0), `ppH3ChunkRows` (2048), `ppH3NoOpt`. New fields start from the main values once (`saved.ppH3PddFile ?? saved.pddFile` ...) and are filled from the saved config once (`take(...)`), then never follow the main ones. `ppH3State(state, kind)` builds the state the graph reads; `ppH3Kind(meta)` = "ref" when the clip's meta mode is "reference", else "fl". User LoRAs are not used; sampler euler, scheduler simple, shift 12/3.
Clip rules: frames are trimmed to 17n+5; Kimchy needs width and height multiples of 32 (error otherwise); size = `sizeForMp(srcW, srcH, Final MP)` (source aspect, 32-aligned).
Graph (`addH3LastStep`):
- H3 Latent Upscaler: VAEEncode(frames) + audio -> TJ_H3_AudioLock -> latent upscale to the final size -> the last sigma interval at the FINAL size (FL2VA: first and last frame of the clip as keyframes; Reference: MiniMaxH3ReferenceToVideo, prompt only) -> decode.
- Kimchy: VAEEncode + audio -> ONE step at the clip's own size (whole picture, with keyframes) -> `KimchyH3ZeroSplitMP` (upscale to Final MP, then its tile step, prompt only) -> decode. `low_sigmas` come from the 8-step schedule after the sigma shift, split at 7.
- Result audio = the source clip's own audio; a source without audio skips the lock.
Prompt rule (`ppH3Prompt`, `writeFromVideo` in `web/minimax/ui_prompt_edit_minimax.js`): a ONE STUDIO H3 clip whose meta prompt is a base brief (`integrated_multimodal_description` or `[Shot 1]`, no `<Picture>/<Video>/<Audio>/@name`, mode not reference) is used as is; anything else (LTX prompt, reference brief, no meta) -> frames about one per second (max 8, min 2) -> vision -> H3 first/last brief with the base prompt system prompt; the answer is cleaned (lines that only map a picture to a time are dropped, leftover `<Picture N>` become "the frame").
Warnings (panel text, not blockers): ratio < 1.3 with the neural upscaler ("This is a ×N upscale. The neural upscaler is made for about ×2 and leaves a diagonal grid on fine textures (hair, fabric) near ×1. ..."); H3 Latent Upscaler above 1.6 MP ("On a 16 GB VRAM card, above 1.6 MP the H3 Latent Upscaler can run out of VRAM and spill to the CPU (an hour or more). 1.6 is its sweet spot; the Kimchy upscaler handles 2.0.").
Measured (16 GB, same clip): neural at ~×1.1 leaves a diagonal grid, bicubic is clean there; at ~×2 neural is clean and bicubic stripes badly. H3 Latent Upscaler 1.6 MP took ~4 min for 10 s; Kimchy ~6-9 min.

### 2c. Meta written by every Postprocess run (Generate, not Preview)
Source meta carried forward, plus `postProcess`, `postSource`, `postUpscale` ({method, ...}), `postPrompt` (the prompt used), geometry (`w`, `h`, `frames`, `fps`, `durationSeconds`, `sourceW`/`sourceH`). Do NOT set `hiresFinish` (Reuse would switch 7+1 on).

Kimchy tile counter "Kimchy tile k/N · running m:ss · tile k took m:ss (s/it)[, incl. load] · avg ... · ETA ..." (N from the node's own window maths, `kimchyTileCount`). Busy banner shows the source clip's first frame behind the text. Clock runs during the job.

## 3. Run recovery after a reload (every long video job)
- The state whitelist (`defaultState`) must keep the run records `_relay` (clip generation), `_ltxRelay`, `_ppRelay`, `_frRelay`; they were being dropped on every reload, which made the old resume code dead. Same fix in the LTX 2.5 core (`_relay`).
- Postprocess: when a run is queued, `state._ppRelay = { ...info, promptId, startedAt }` (info = saveNode, usedSteps, upscaleUsedInfo, usedPrompt, full, startS, endS, source, sourceMeta, sourceFullMeta, kimTiles, kimLo, barBase, h3, nodeId). A split run keeps `{ v: 2, seg: true, args, passes, parts, curPromptId, info }`. On load, 1.5 s after the node is on the graph and its saved state is back (the node has no id while it is constructed): if the record is this node's (`nodeId`), look the prompt up in the queue and `/history`; running or finished -> reattach (`waitForHistory`), show progress, `fixAudioSuffixes` (strip VHS "-audio"), show the result and write the meta (`ppFinish`); unknown -> clear it and say "the run did not survive the reload (ComfyUI has no record of it)". A split run continues with the next piece (or reattaches to the one in flight). Each run is picked up once (window-level key) so two copies of the node cannot finish it twice. The Kimchy tile line says "reconnected: tile numbers restart here, the run itself is unaffected".
- `fixAudioSuffixes(byNode)` is now a shared export of `api_minimax.js`, also used by `waitForHistory` when it returns completed outputs.
- The queue call must keep sending VHS_KeepIntermediate=false and VHS_MetadataImage=false in extra_data (no silent copy, no PNG).

For the web twin (AI-ONE-STUDIO) and Canvers (card/graph structure: report "not applicable" for anything that does not fit). Server side: nothing to port (same ComfyUI; the new modes only use core nodes present in ComfyUI 0.43+). Node verification: UI loaded in the browser (tabs, auto-picked LoRAs/MoGe model), graph structure checked against `/object_info` (all classes/inputs/links valid), and **both graphs rendered for real** on this PC (I2I Depth 512x512 / 8 steps, EDIT 0.5 MP / 10 steps, both `success`). Not verified: the Send-to buttons by hand, gallery "→ Edit", Auto Enhance with the EDIT system prompt.
Source of truth: node `web/moss/` — `core_moss.js` (state + manual text), `graph_builder_moss.js` (`buildDepthGraph`, `buildEditGraph`, `baseGraph(state, opts)`, `sample(...)`), `ui_i2i_moss.js` (tabs, `mountDepthPanel`, `mountModeLora`), `ui_edit_moss.js`, `one_node_moss.js` (MODES, SEND_TO, `applySentImage`), `system_prompt_moss.js`, `ui_gallery_moss.js`, `api_moss.js` (`getObjectOptions`).

## 1. Mode bar (order matters)
`T2I · R2I (bboxes) · I2I · EDIT · INPAINT` (was T2I · I2I · R2I · INPAINT). Keys: `t2i, r2i, i2i, edit, inpaint`.
- **I2I** gets two tabs at the TOP of its left menu (above the Source Image panel): `Basic` | `Depth` (state `i2iSubMode`: `"basic"` default | `"depth"`). Basic = the existing I2I (Denoise slider). The source image and W/H/Lock-ratio panel are shared by both tabs; only the part below changes (Denoise slider for Basic, Depth panel for Depth), then the shared Steps/CFG/Sampler/Scheduler/SLG panel and the LoRA section for both. Both tabs use the prompt slot `promptsByMode.i2i`.
- **EDIT** is a new top-level mode (prompt slot `promptsByMode.edit`).

## 2. New state keys (add to `defaultState`; all optional, saved with gallery meta)
I2I Depth: `i2iSubMode` ("basic"), `depthLora` (""), `depthLoraStrength` (1), `depthMoge` (""), `depthOutput` ("mask"), `depthStrength` (1), `depthStart` (0), `depthEnd` (0.6).
EDIT: `editImage` (null), `editRefs` ([] , max 3 filenames), `editLora` (""), `editLoraStrength` (1), `editFormat` ("Moss-Image-Edit"), `editImageStrength` (1), `editMp` (1), `editSteps` (30), `editCfg` (4), `editSampler` ("euler"), `editScheduler` ("normal").
LoRA / MoGe model are picked in the panel, not in Settings. When empty, auto-pick the first installed LoRA matching `/color_depth_control/i` (depth) or `/moss_image_edit_lora/i` (edit), and the first MoGe model matching `/vitg/i` else the first. Choices come from `/object_info/LoraLoaderModelOnly` (`lora_name`) and `/object_info/LoadMoGeModel` (`model_name`) — read both `[[...]]` and `["COMBO",{options:[...]}]` formats (`getObjectOptions`).

## 3. I2I > Depth panel (below the source panel)
1. `Control LoRA (strength)`: select (all LoRAs, "none" first) + number (0–2, step 0.05, width 60px). Hint under it: `moss_image_color_depth_control (models/loras): without it the control map is ignored.` (turns into `⚠ …` in the warn colour while none is chosen).
2. `MoGe model (geometry estimation)`: select; if no MoGe model exists show the warn text `⚠ No MoGe model found: put moge_3_vitg_fp16.safetensors in models/geometry_estimation (Comfy-Org/MoGe) and update ComfyUI (0.43+) for the MoGe nodes.`
3. `Geometry used as control`: select `mask` = "Silhouette (mask) — pose only, prompt has room" | `depth` = "Depth — also face profile, shoulders, background falloff"; three number fields `Strength` (0–2, .05), `Start` (0–1, .05), `End` (0–1, .05); note text: `Strength 1.0 is the trained value. Start / End pick the part of the run that is controlled: 0 to 0.6 fixes the layout and lets the last steps render freely; End 1.0 pins the geometry to the last step. Sampling uses the official control preset (temporal score rescaling 0.95, shift 5, skip layer guidance layer 24); CFG 3 and 25 steps are recommended.`
Errors on Generate: `Depth control LoRA is not set: pick moss_image_color_depth_control in the I2I > Depth panel.` / `No MoGe model selected: pick one (models/geometry_estimation) in the I2I > Depth panel.` / `No source image uploaded for I2I.`

## 4. Graph: I2I Depth (`buildDepthGraph`, api node ids `MS:*`)
`baseGraph(state, {first:[control LoRA], noSlg:true})`: `MS:unet` (UNETLoader or UnetLoaderGGUF) → `MS:first0` LoraLoaderModelOnly(control LoRA, strength `depthLoraStrength`) → your LoRAs (`MS:lora{i}`) ; `MS:clip` CLIPLoader(type `moss_image`), `MS:vae` VAELoader, `MS:negative` CLIPTextEncode(negative prompt).
Model patches, in this order: `MS:tsr` TemporalScoreRescaling(model, tsr_k 0.95, tsr_sigma 1) → `MS:shift` ModelSamplingAuraFlow(shift 5, sampling "flow") → `MS:slgd` SkipLayerGuidanceDiTSimple(double_layers "", single_layers "24", start 0, end 1). The user's own SLG checkbox is ignored in this tab.
Image: `MS:src` LoadImage(i2iImage) → `MS:fit` ImageScale(lanczos, width snap16(i2iWidth||width||1024), height snap16(i2iHeight||height||1024), crop "center") → `MS:mogeLoad` LoadMoGeModel(model_name) → `MS:mogeInfer` MoGeInference(moge_model, image fit, resolution_level 9, fov_x_degrees 0, batch_size 4, force_projection true, apply_mask true, refine_steps 3) → `MS:mogeRender` MoGeRender(moge_geometry, output `depthOutput` "mask"|"depth").
Conditioning: `MS:positive` CLIPTextEncode(prompt i2i) → `MS:control` MOSSImageControl(positive, negative `MS:negative`, vae, strength `depthStrength`, start_percent `depthStart`, end_percent `depthEnd`, depth_map = MoGeRender). `MS:latent` EmptyFlux2LatentImage(width, height same as `MS:fit`).
Sampler: shared `sample()`: KSampler(model `MS:slgd`, positive `MS:control`[0], negative `MS:control`[1], latent, seed, **the panel's Steps / CFG / Sampler / Scheduler**, denoise 1) → VAEDecode → Save/Preview. `buildI2IGraph` dispatches to `buildDepthGraph` when `i2iSubMode === "depth"`, otherwise unchanged.

## 5. EDIT panel (`ui_edit_moss.js`), top to bottom
`Source Image` upload (+ hint `Describe only the change in the prompt: "Change only the X to Y. Keep the face, pose, background and composition unchanged."`); `More references (up to 3) — say in the prompt what each is for` with `+ Add reference` and per-reference ✕ (uploads labelled `Reference 2..4`); `Edit LoRA (strength)` (same widget as the control LoRA; hint `moss_image_edit_lora_rank_64_bf16 (models/loras): the edit layout is trained into this LoRA.`); `Edit format (must match the LoRA)` select (choices from `/object_info/TextEncodeMOSSImageEdit` `edit_format`; fallback `Moss-Image-Edit`, `ai-toolkit`, `ai-toolkit (kv_cache off)`); `Image strength` (0–2) and `Size (MP)` (0.25–4, step 0.25) with note `The source and the references are scaled to this many megapixels (16 px steps); the result keeps the source's aspect ratio. About 0.26 MP is cheaper but looser: the model starts re-framing the subject.`; Steps (1–100) / CFG (0–20, .25) / Sampler / Scheduler (own fields, defaults 30 / 4 / euler / normal) with note `CFG 4 matters: the negative branch is what stops accessories appearing out of nowhere. Skip layer guidance (layer 22) is always on for EDIT.`; then the normal LoRA section (your LoRAs).
Prompt placeholder in EDIT: `Change only the X to Y. Keep the face, pose, background and composition unchanged.`
Errors: `No source image uploaded for EDIT.` / `Edit LoRA is not set: pick moss_image_edit_lora_rank_64_bf16 in the EDIT panel.`

## 6. Graph: EDIT (`buildEditGraph`)
`baseGraph(state, {first:[edit LoRA], noSlg:true, noNegative:true})` → `MS:slgd` SkipLayerGuidanceDiTSimple(single_layers "22", 0–1). Source + refs: each `MS:ref{i}Load` LoadImage → `MS:ref{i}` ImageScaleToTotalPixels(lanczos, megapixels `editMp`, resolution_steps 16) (i = 0 source, 1–3 refs). `MS:positive` and `MS:negative` are both TextEncodeMOSSImageEdit(clip, prompt = edit prompt / negative prompt, edit_format, image_strength, vae, `images.image_0` … `images.image_N` = the scaled images, same images on both). `MS:size` GetImageSize(ref0) → `MS:latent` EmptyFlux2LatentImage(width = size[0], height = size[1]). KSampler(model `MS:slgd`, positive, negative, latent, seed, steps `editSteps`, cfg `editCfg`, sampler `editSampler`, scheduler `editScheduler`, denoise 1) → VAEDecode → Save/Preview.

## 7. Send to / connections (important — the user asked for care here)
Per mode, the "Send to:" buttons under the preview (copy the result into input/, set it as the target's source, switch mode):
`t2i` → I2I, Edit, Inpaint · `r2i` → I2I, Edit, Inpaint · `i2i` → Edit, Inpaint · `edit` → **Edit** (chain edits on the result), I2I, Inpaint · `inpaint` → I2I, Edit.
Target field per mode: I2I `i2iImage`, Edit `editImage`, Inpaint `inpaintImage`. Gallery card buttons: `→ T2I (reuse)`, `→ I2I`, **`→ Edit`**, `→ Inpaint` (same fields). Both paths go through `applySentImage(mode, field, filename)`: set the field; read the image's natural size and set `i2iWidth/i2iHeight` (I2I, snap16) or `inpaintWidth/inpaintHeight` (Inpaint, snap16) — EDIT needs none (megapixels); for **Inpaint also clear `inpaintMask`** (a mask painted on another picture no longer fits); then switch mode and re-render. (Before this change Send-to left the previous upload's size in place, which distorted the aspect.) Sending to I2I keeps the current tab (Basic/Depth). Compare view (source vs result) is on for i2i, edit and inpaint.

## 8. Auto Enhance / Prompt Enhance system prompt for EDIT
`mossSystemPrompt(mode)`: `r2i` → R2I prompt, **`edit` → new `MOSS_SYSTEM_PROMPT_EDIT`**, anything else → T2I prompt. Text (English, verbatim from node `system_prompt_moss.js`): "You rewrite a user's image-edit wish into one short instruction for the MOSS-Image Edit model. Rules: - Output ONLY the instruction, in English, no preamble, no quotes, no markdown. - Form: "Change only the <what> to <how>. Keep the character, face, hair, pose, background and composition unchanged." Name the thing that changes precisely (colour, material, garment, object) and what it becomes; name what must stay as it is. - If several references are mentioned, say what each one is for (e.g. "Use the jacket from the second image."). - Do not describe the whole picture, do not add new people, objects or accessories, do not change the style unless asked. - Keep any text that must appear in the image exactly as written." (Not from the official templates.)
